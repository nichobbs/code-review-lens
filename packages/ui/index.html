📖 Reviewer Guide & Human Focus
🎯 Where Humans Add Maximum Leverage

AI lenses verify mechanical rules, syntax, and local control flow. Spend your human review budget on the 4 high-leverage judgment areas AI cannot decide alone:

  • 1. Business Intent & Operating Load: Does the change solve the right problem for the expected load (single-user CLI, batch job, or high-concurrency service)?
  • 2. PLAUSIBLE vs CONFIRMED Findings: CONFIRMED findings are proven in the diff. PLAUSIBLE findings have a real code path but depend on prod config, upstream callers, or real traffic shapes—use your domain knowledge to Block or Dismiss.
  • 3. Silent Removals & Scope Creep: Check Removed Guards (deleted auth, schema validation, or retry checks), Negative-Space Violations (files marked Out of scope), and Stealth Changes (core files modified without mention in the PR description).
  • 4. Bounded Shortcuts vs Rot Risk: Respect // shortcut: <ceiling>, <upgrade> when load stays below <ceiling>. Challenge unbounded TODO/FIXME comments flagged as Rot Risk.
🧭 How to Review the 4 Layers
Layer 1 · Intent & Architecture

Read What it does, the C4 diagram, Human Focus bullets, and the automated Attention & Shortcut Ledger before looking at individual files.

Layer 2 · Verified Risk Findings

Step through findings with j/k. Inspect the inline diff slice and Verifier proof. Triage each as 🚫 Block (b), 💬 Comment (m), or 🔇 Dismiss (x).

Layer 3 · Contracts & Story Flows

Audit public API/event/schema changes first. Check CODEOWNERS badges and External Caller Blast Radius—especially (unowned) callers outside the PR.

Layer 4 · Behavioral Test Matrix

Skip raw mock boilerplate. Scan the behavior table for hollow (0 assertions), tautology (asserting constants), internal-mock (mocking internal helpers), and uncovered EARS/BDD spec clauses.

⚡ Triage, Agent Prompts & Publishing
  • Batch Presets: In Layer 1, use Block Highs · Comment Medium/Design to pre-triage in one click, then refine individual items.
  • Human Reviewer Notes: Add context in the note box on any finding—it is included in both the GitHub PR thread and the Coding Agent prompt.
  • Publish to GitHub: Click Publish to GitHub to post inline <!-- crv-finding --> threads + a sticky summary comment (live publish is on by default; pass --dry-run on the CLI for local-only mode).
  • Hand Off to Coding Agent: Click 🤖 Copy Agent Fix Prompt on a finding (or Copy Agent Prompt in the top bar) to paste curated fix instructions into your AI coding agent.
